## 背景

本番コード 25 ファイル / 約 1,120 行に対して、`Commons` / `Interface` / `InteractionItems` / `ModelFactories` / `DAO` / `Models` / `Controllers` という 7 つの層を持つ。この分類は *OO 上の役割* を表しており、実際に強制したい *依存の向き* を表していない。結果として:

- グローバル可変状態（`Common.DAO`）が生成順序の暗黙の前提になっている
- `vscode` API が Model 層まで侵入し、**12 個のユニットテストのうち素の Mocha で動くのは 2 個だけ**
- 設定の扱いに 3 つの連鎖したバグ（`grep2file.exclude: []` を設定すると全ファイルが除外される）

目標は、規模に見合った量の抽象化 — **ポートは 4 つだけ、DI コンテナもバンドラも導入しない** — で依存の向きを一方向に揃え、純粋なロジックをヘッドレスにテスト可能にすること。
